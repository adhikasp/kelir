# M12 — publish preparation (the push itself needs the maintainer's explicit yes)

The spec says the repo is public (`github.com/the maintainerasp/kelir`); expectation was a public repo early. Publishing is
outward-facing and irreversible-ish, so the orchestrator prepares everything and **stops for the maintainer's
confirmation before the first push**.

## Prepare (no push)
1. **History scrub**: the git history carries a personal email in author fields and early commits name hosts/people.
   Produce a clean history for publication: `git filter-repo` (or an equivalent export) into a *new* directory/branch,
   author/committer rewritten to a public identity, a `.mailmap`, messages scrubbed with the pattern file
   (scripts/scrub-check.sh, patterns kept outside the repo), reviews/retros/briefs kept only if scrub-clean.
   Verify with scrub-check over **all** objects (`git log -p` / `git grep` across history), not just the tree.
2. **First CI run**: `.github/workflows/ci.yml` has never executed. Run it locally with `act` if available, or lint it
   (actionlint), and verify the three-OS matrix assumptions (ubuntu, macos, windows): no hardcoded Windows paths in
   tests that run on macOS, tests that need `the maintainer`-style remotes are skipped without the env, `cargo` caching. Fix
   what a dry review finds; the real run happens after the push.
3. **Repo hygiene**: README (what/why, install, config, the two providers, safety stance of a fully autonomous
   agent), LICENSE (MIT — decided by the maintainer), SECURITY.md,
   CONTRIBUTING (the worktree/gates workflow), issue templates optional, `Cargo.toml` metadata (repository, license,
   description) — no personal data.
4. **Release prep**: version, changelog from PROGRESS.md, `cargo publish --dry-run` (crates.io name checked free).
5. Output: `docs/PUBLISH.md` with exactly the commands to run, what was scrubbed, the checklist; the scrubbed repo
   ready at a path.

## Gate
Fresh reviewer verdict on the scrubbed export (secrets, names, emails, hosts, paths, tokens) and on the docs; then
the orchestrator asks the maintainer (AskUserQuestion) before `gh repo create` / `git push`. Nothing is pushed
without that answer.
