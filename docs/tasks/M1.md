# M1 — verbs over the session socket

Prereq: M0 fixes merged and green. Read `docs/SPEC.md` sections *Process model*, *Verbs*, *Loop and
boundaries*, *Shell and platforms*. Also finish N2 from the M0 review (child must be inside the
Job Object / process group before it can run user code).

## Build

1. **Session socket** — `<session dir>/sock` (Unix socket) / named pipe on Windows, via the
   `interprocess` crate. Served by the session process (`kelir run`), newline-delimited JSON:
   request `{"verb": "...", "args": {...}}` → one response line `{"ok": true, ...}` or
   `{"ok": false, "error": "..."}`. Also exported to every bash child as `KELIR_SOCK`.
   Session discovery: `kelir ctl <session-id|prefix|latest> …` resolves from the state dir.
2. **Verbs** — `say [--now]`, `later`, `stop [--call <id>] [reason]`, `model <provider/model>`,
   `tools --disable|--enable <name>` exactly per the spec's table, each appending a `verb` event
   (applied or not) and then applying at the named boundary. `kelir ctl <session> <verb> [json]`
   and flags (`--now`, `--call`).
3. **Boundaries** — implement the `before_step`/`after_tools`/`after_step` enum in the loop, applied in
   one `select!` arm. Never between a tool call and its result. `say --now` stops running calls
   (kill the process tree: `killpg` on Unix, Job Object terminate on Windows), settles each as
   `stopped` (running) or `skipped` (not yet started) with results the model can read, then injects
   the message. `stop` ends the turn (`turn_ended outcome=stopped`), keeps partial work.
   `stop --call <id>`: that call returns `stopped by user: <reason>`, the turn continues.
4. **`model`** swaps provider/model for the rest of the session, applying at the next step
   (`step_started` records it). Cache restart is expected and logged.
5. **`tools`** — the tool list sent never changes; a disabled tool's call returns `disabled by user`.
6. **`later`** — queued, delivered at turn end as a user message with `delivery: later`, starting a
   new turn within the same process (headless `run` waits for queued `later` messages before exiting).
7. **Headless idle**: a `kelir run --keep` flag keeps the session process alive after the turn ends,
   accepting `say`/`later` to start new turns, until `kelir ctl <s> end` (a small extra verb, log
   `session_ended`). Needed to drive it from other terminals and by the TUI in M2.

## Tests (pyramid)

- **Unit**: verb parsing/validation; the boundary state machine (pure function: pending verbs +
  loop state → actions); `later` queue ordering; `tools` disabled-call result; session-id resolution.
- **E2E** against the mock server (extend it with delays and a gate to hold a response): `say` mid-turn
  is in the next request; `say --now` during a `sleep 30` stops it within 2 s and the next request
  has the `stopped` result then the message (never between call and result); `stop`; `stop --call` on
  one of two parallel sleeps, the other finishes and the turn continues; `model` swap changes the
  next request's `model` and shows in `step_started`; `tools --disable bash` → `disabled by user`
  while the request's `tools` array is byte-identical; `later` starts a second turn; `end`; a verb
  sent to a dead session errors cleanly; two concurrent clients. Windows and Unix both compile.
- Assert on `events.jsonl` (`verb` events present, in seq order) and on what the mock received.

## Live drive (reviewer)

1. Pane A: `kelir run --keep --json "run sleep 120 then say done"`; pane B: `kelir ctl latest stop --call <id>` → turn continues with the stopped result; model reacts.
2. `say --now "change of plan: just print hello"` during a long sleep → obeyed at the next step; `sleep` process gone (verify no orphan).
3. `model` swap mid-session to a different cheap model; next `step_started` shows it; cache hit resumes after one step.
4. `kelir ctl` against a killed session: clear error, no hang. Windows: confirm named pipe works from a second shell.
