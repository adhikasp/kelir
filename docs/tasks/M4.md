# M4 — background jobs

Prereq: M3 green. Read SPEC *Background*, *Shell and platforms* (10-minute promotion, detached bg),
*Process model* (bg jobs while the session is not running), event types `bg_started`/`bg_settled`.

## Build
1. `kelir bg run <cmd…> | ls | out <id> [--follow] | wait <id> [--timeout] | cancel <id>`. A job runs
   under `kelir bg-shim` (same binary) that spawns the command, tees output to a file, and writes
   `bg/<id>.status` (JSON: state, pid, exit_code, started, finished) **atomically** (write+rename).
   The job outlives the session: Unix `setsid`, outside the session's process group; Windows
   `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`, **outside** the session's Job Object (create it
   with `CREATE_BREAKAWAY_FROM_JOB` or otherwise make sure it is not in kill-on-close).
2. `kelir bg` is reached from inside a bash call via `KELIR_SOCK` (the session records
   `bg_started`/`bg_settled`); outside a session it works standalone against the state dir.
3. **Promotion**: a bash call past `promote_after` (default 600 s; config + `KELIR_PROMOTE_AFTER`
   env for tests) is handed to the shim machinery without being killed (outcome `promoted`, result
   tells the model the bg id and how to read it). Output captured so far is kept. Implementation hint:
   to promote a running child that was not started under the shim, either always start bash calls via
   the shim (cleanest; the shim is then the call's process owner and promotion is just "stop waiting")
   or keep the child and re-parent its bookkeeping. Choose, record in DEVIATIONS.md.
4. **Wake**: when a bg job settles while the session runs, append `bg_settled` and admit a message
   at the next boundary (`source` kind `job`?? — use a `user` event with `from: job`) so the agent wakes.
   Not running: nothing happens; `kelir resume` folds `bg/*.status` into the log as `bg_settled`.
5. Exit codes and cancel: cancel kills the job's process tree; status `cancelled`.

## Tests
- **Unit**: status-file atomic write/read, torn status tolerance, id generation, promotion timer
  logic (injectable clock), fold of `bg_settled`.
- **E2E (mock)**: job lifecycle with `KELIR_PROMOTE_AFTER=1`: `sleep 3` promoted, call returns
  `promoted`, bg job finishes, wake message arrives; kelir process exits (kill) mid-job, job
  survives (pid alive), `kelir bg out` reads it, `resume` logs `bg_settled`; cancel kills a tree
  (child of child); Windows and Unix variants.
