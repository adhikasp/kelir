# M0 — one-file loop

Read `AGENTS.md` and `docs/SPEC.md` first (all of it, especially Event log v0, Prompt caching, Big
outputs, Providers, Shell and platforms).

## Build

A single crate `kelir` (binary `kelir`), edition 2024 if the toolchain allows, with:

1. **Providers** — one OpenAI Chat Completions streaming client (reqwest + rustls). Config entries
   for `openrouter` and `opencode-go` (base URL, key env var, extra headers, `reasoning_field`).
   Key env vars: `OPENROUTER_API_KEY`, `KELIR_GO_API_KEY`. Go base URL
   `https://opencode.ai/inference/go/v1` (verify the path against the spec; keep it configurable),
   header `x-opencode-session: <session id>` and `User-Agent: kelir/<version>`. OpenRouter: body
   `session_id`, top-level `cache_control` only for Anthropic/Qwen model ids, never `provider.order`.
   `stream_options.include_usage` always on. A base URL override env/flag (`KELIR_BASE_URL`) so the
   mock server can stand in for either provider.
2. **Config** — `config.toml` search per spec (state/config dirs per OS via `dirs`-like logic or the
   `directories` crate), CLI flags override. Keep it minimal: provider, model, shell, spill limit.
3. **Tools** — `bash` (runs via the configured shell; default per OS; process-tree kill on stop is
   M1 but spawn it in its own process group / Job Object now so it is possible; tee output to
   `commands/<call-id>/out`; exit code; ≥10 KB results become the spill notice with 1 KB head+tail
   and an rg/sed hint) and `edit` (exact-once replace, `replace_all`, create on empty `old` for a
   missing file, preserves CRLF, returns changed line numbers). Parallel tool calls in one
   assistant message run concurrently; results appended in call order.
4. **Event log v0** — `events.jsonl` exactly per spec for the types M0 touches: `session_started`,
   `user`, `step_started`, `assistant`, `usage` (with `cached_tokens`, `cache_write_tokens`, `cost`),
   `tool_started`, `tool_settled`, `turn_ended`, `error`, `session_ended`. Monotonic `seq`, fsync per
   batch, session dir layout per spec, `ses_<ulid>` ids.
5. **fold** — context is always `fold(events.jsonl)`; the request builder uses only the fold. The
   frozen system prefix is recorded in `session_started`.
6. **CLI** — `kelir run [--json] [--model M] [--provider P] "<task>"` (task also via stdin),
   NDJSON of the events on stdout ending with a `result` event and exit code (0 done, 1 error,
   2 usage); `kelir ask "<q>"` one-shot (no tools beyond what the loop needs, prints final text).
   Human-readable (non-`--json`) mode prints assistant text and a compact tool line.
7. **CI** — `.github/workflows/ci.yml`: fmt, clippy `-D warnings`, test on ubuntu, macos, windows.
   (Do not push; it just has to be valid.)

## Test requirements (the pyramid)

- **Unit**: SSE chunk parser (incl. split chunks, tool-call deltas assembled across chunks,
  `[DONE]`, usage-only final chunk), fold, edit semantics (every branch, CRLF), spill threshold
  boundaries (exactly 10240 vs 10241 bytes, non-UTF-8), request builder (headers per provider,
  `session_id`, `cache_control` rules, prefix only grows across steps), event serialization
  round-trip, torn-last-line tolerance, call-order result ordering with out-of-order completion.
- **E2E** (`tests/`): an in-process mock OpenAI-compatible SSE server with scripted turns. Cases:
  plain answer; one bash call; two parallel bash calls where the second finishes first; edit then
  bash; a >10 KB output spills; an HTTP 500 then success (retry with backoff, `error` event with
  `retryable`); mid-stream disconnect; the mock verifies (a) `x-opencode-session` and
  `kelir/` User-Agent on the Go path, (b) `session_id` on the OpenRouter path, (c) the request
  prefix of step N+1 begins byte-identically with step N's request messages, (d) usage cache
  fields land in `usage` events. Assert on `events.jsonl` and on NDJSON stdout.
- Run on this machine (Windows) now; make sure Unix paths compile via `cfg` (CI covers them).

## Done when

`cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test` is green, a
release build runs `kelir run --json "say hi"` against the mock, and you have appended a row to
`docs/PROGRESS.md` (live drive column: `pending reviewer`). Commit as `M0: …`. Then
`hc send $HC_TERMINAL_ID "M0 ready: <commit> <test counts>"`.

Do NOT call real providers yourself; the reviewer does the live drive.

## Live drive (reviewer)

1. `kelir run --json "Create hello.txt containing the word hi using the edit tool, then cat it with bash and tell me what it says."` in a scratch dir, OpenRouter cheap model: log has `tool_started`/`tool_settled` pairs, a final answer, `jq` works on the NDJSON.
2. The fixed M0 task in miniature: a scratch git repo with a tiny Rust or Python CLI + test; ask kelir to add a flag and a test and make the suite pass (≈10-20 steps). Report step count, cost, and per-step `cached_tokens` — **expect `cached_tokens > 0` from step 2** on OpenRouter; if not, find out why (request body, `session_id`, model's caching behaviour) and report it.
3. Parallel calls: ask it to run `sleep 3` twice in one message; confirm wall time < 6 s and results in call order.
4. A command printing > 10 KB: confirm spill notice, file on disk, model can `sed -n` it.
5. Windows shell: confirm which shell `bash` resolved to and that CRLF files keep CRLF through `edit`.
