# M11 — attach viewer and notifications

Milestone row: "`attach` viewer + notifications | `hc wait` sees kelir; the viewer is under 10 MB". Goal: watch (and lightly steer) a running or finished session from another
terminal, and get told when long work ends, without a daemon.

## Build
1. **`kelir attach <session|name> [--follow] [--since N]`**: a read-only live viewer of a session (running or finished): replays the event log through the same row model as the TUI
   (docs/reference/tui.md: state row, collapsed tool calls, markdown, outcome lines) in an inline viewport, then follows new events (tail of events.jsonl with torn-line tolerance, plus the
   session socket for liveness/status). It never writes to the log; a viewer disconnecting never affects the session. `--raw` prints NDJSON; `--plain` prints un-styled text for pipes.
   Interactive steering from the viewer is limited to the existing verbs (`say`, `stop`) sent over the socket WITH the session token (the human `kelir ctl` path), behind an explicit
   key/command (default read-only). Works for child sessions (M7) and named sessions (M9), and on Windows and Unix.
2. **Footprint**: the viewer process stays under **10 MB working set** while following a session with 100k events (measure on both OSes; stream the log with bounded memory, never load
   it whole; cap the rendered backlog). If the single binary cannot meet this, add a small separate entry (`kelir attach` re-exec or a cargo feature) and document it; the main binary
   stays <= 20 MB.
3. **Herdr visibility**: `hc wait` must see kelir: a session in a Herdr pane reports working/idle/done/error (OSC status, M2) for `kelir`, `kelir run`, `kelir job run`, `kelir channel`
   and `kelir attach` (the viewer reports nothing: it is not an agent); verify with real Herdr panes (`hc run --bg`, `hc wait`, `hc get`), including a headless `kelir run --json` job
   in a pane. Root sessions only (children never report).
4. **Notifications**: configurable hooks `[notify]` in config.toml and per job: on `turn_done`, `error`, `paused`, `bg job settled`, `child settled` run a command (scrubbed environment,
   30 s timeout, never blocks the session, rate-limited) and/or emit a terminal notification (OSC 9 / OSC 777, only when stdout is a TTY and enabled). Shipped examples under
   examples/notify (generic): a desktop toast on Windows (PowerShell), `notify-send` on Linux, `osascript` on macOS. Nothing is enabled by default. Events are logged (`notify` event with
   outcome) like gate events.
5. Docs: SPEC reconciled (DEVIATIONS), docs/reference (attach.md, notify.md, cli, config, events), drift test passes.

## Tests (pyramid)
Unit: tail reader (torn lines, rotation-free append, huge lines, backlog cap), row model reuse (snapshot against the TUI for the same events), notify hook runner (scrubbed env, timeout, rate
limit), OSC emitters. E2E: attach to a live mock session sees events as they arrive and the final state; attach to a finished session replays and exits; attach to a dead/torn session dir;
read-only guarantee (no writes to the session dir by the viewer: compare directory snapshots); say/stop via attach need the token; RSS measurement with a 100k-event log on both OSes;
notify hook fires once per event kind with the right environment and never blocks; `hc wait` sees a real `kelir run` in a pane (live, Herdr). Process-count watchdog, no leaked processes,
no console windows. Live drive: attach from a second pane while a real cheap-model session runs.
