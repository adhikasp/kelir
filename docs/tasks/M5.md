# M5 — sources, skills, hint, memory, attachments, observe

Prereq: M4 green. Read SPEC *Sources, skills and memory*, *Prompt caching*, `source` event,
`kelir observe`.

## Build
1. **Sources**: base `prompt.md` (embedded default ≤ 1 KB, overridable in config dir), instruction
   files found walking up from cwd (`AGENTS.md`, `CLAUDE.md`), skills directories (config
   `skills_dirs` + `~/.claude/skills`, `.claude/skills`, `.kelir/skills`, read-only). Two layers,
   machine then project, project wins on a name clash. Rendered **once** into the frozen system at
   `session_started` with `sources[]` (name, path, hash). Date in, never time.
2. **Mid-session changes** arrive as `source` events (rendered as a tail message), never as a system
   rewrite: a file watcher or a per-turn mtime/hash check on the recorded sources; `skills` verb adds
   or replaces a skill/instruction source.
3. **Skills**: Agent Skills format (`SKILL.md` front matter `name`, `description`, optional
   `metadata`). Pull model: the base prompt names the directories; no listing in the prompt.
4. **Pushed hint**: one scoring call per user prompt; provider-agnostic: configurable
   (`hint.provider`, `hint.model`, `hint.endpoint`; default off if unconfigured). Scores skills and
   MCP servers; appends `might be relevant: name — description` (never a body) as a `source`
   `kind: hint` message. **Fails open** on missing key, timeout (2 s default) or garbage. Implement
   the scorer behind a trait with a mock for tests; the first real implementation may use a cheap
   Chat Completions model returning JSON names.
5. **Memory**: a configured memory directory loaded as sources at session start; the model writes
   it with `edit`; changes made mid-session arrive as `source` messages.
6. **Attachments**: `kelir run --attach file…`, `ctl attach`: images go to the prompt as image parts,
   audio/video: store the file and note it as a `source` (transcription/frames are a later hook;
   document it). Event `user.attachments[]`.
7. **`observe`**: `kelir observe <session>` (and verb over the socket) prints exactly what the model
   will see next: system, tools, messages, token estimate, sources, hint, cache hit ratio from
   `usage`. `--raw` prints the exact JSON request body that would be sent.

## Tests
- **Unit**: source discovery precedence (project over machine, nearest AGENTS.md), skill front
  matter parsing (incl. malformed), hint parser fail-open cases, system render determinism (same
  inputs → identical bytes), mtime-change → `source` event, attachments encoding.
- **E2E (mock)**: `observe --raw` equals, byte for byte, the body the mock received for the
  next request (the headline test); a hint appears and the **request prefix stays byte-stable**
  across it (mock asserts prefix growth); editing an instruction file mid-session adds a `source`
  tail message and no system change; hint timeout fails open; 10 held-out prompts hint test with a
  scripted scorer proves wiring (the quality check is live).
