# M2 — inline TUI + Herdr status

Prereq: M1 green. Read SPEC *Scriptable, TUI and Herdr status*, *Verbs*.

## Build
1. `kelir` with no subcommand (and `kelir tui [--resume id]`) starts an interactive session **in the
   session process** (same process model as `run --keep`): ratatui with an **inline viewport**
   (`Viewport::Inline`): finished turns go to scrollback via `insert_before`; only the input box and
   a status line (model, step, tokens, cost, cache hit ratio, running calls) repaint.
2. Streaming assistant text renders live in the inline area, then is committed to scrollback.
   Tool calls show as compact lines (`$ cmd`, exit code, bytes, spilled), output tail on demand.
3. Input: multi-line editor (Enter sends, Alt/Shift-Enter newline), `/` commands that map 1:1 to
   verbs: `/stop`, `/say-now`, `/later`, `/model p/m`, `/tools`, `/compact` (stub until M3),
   `/quit`. Ctrl-C = `stop`; second Ctrl-C within 1 s = quit. **Every TUI action is also a `ctl`
   verb**: implement the TUI by sending verbs through the same internal command path as the socket,
   and add a test that enumerates TUI actions and asserts each has a verb.
4. OSC 7501 Herdr status writer (`app=kelir`, root session only): `working` at turn start, `done` on
   success, `idle` on stop, `error` with `msg`; `idle` instead of `done` if `TERM_PROGRAM=herdr-telegram`.
   Never `blocked`. Exact sequence format: copy what existing agents emit if discoverable
   (`herdr-app --skill`, Herdr docs on this machine); otherwise document the format you used in
   DEVIATIONS.md. Written only when stdout is a TTY or `KELIR_HERDR=1`.
5. Non-TTY fallback: `kelir` without a TTY prints a usage error, never hangs.

## Tests
- **Unit**: input editor state machine; command-line parsing (`/model p/m` → verb); status-line
  formatting; OSC sequence builder; scrollback line wrapping/committing logic as pure functions.
- **E2E**: ratatui `TestBackend` snapshot tests for the inline area (idle, streaming, running call,
  error); the "every TUI action has a verb" enumeration; headless PTY test if a PTY crate is
  already feasible (`portable-pty` dev-dependency is allowed) driving the real binary against the
  mock: type a prompt, see the answer in the scrollback, `/quit`.
