# M3 — durability and compaction

Prereq: M2 green. Read SPEC *Durability*, *Compaction*, *Event log v0* (`resumed`, `compacted`,
`error`), *Loop and boundaries*.

## Build
1. **Durability**: fsync per batch (verify it really is, and that a batch is atomic enough: a torn
   last line is detected, skipped, reported as an `error` event on resume). Never lose more than the
   in-flight step.
2. **`kelir resume <id>`** (and `kelir tui --resume`, `kelir run --resume <id> [task]`): fold the
   log, append `resumed {from_seq, unsettled[]}`, continue. A `tool_started` without
   `tool_settled` is reported to the model as a tool result "unknown outcome: kelir was interrupted
   while this call was running; it may or may not have completed. Check before retrying." and is
   **never re-run**. A stopped or crashed turn continues from the log with the model's next step.
   A stale `sock` file from a dead process is replaced.
3. **Compaction**: the `compact` tool (add it to the fixed tool list now, with optional `focus`),
   the verb/`/compact [focus]`, and auto at 80 % of the model's window (window from config,
   default per-model table, overridable). Applies at the next boundary after the batch settles.
   Summarising request uses `compact.md` (embedded default, overridable in config dir). The
   `compacted` event holds the summary and `pinned_seqs`; **pins verbatim the first user message
   and every human-typed `user` message**. `fold` replaces the compacted range with the summary +
   pins. Spill/blob files untouched. `tokens_before/after` recorded. Cache restart is logged.
   (`spawn` arrives at M7; keep the tool list definition in one place.)
4. `session_ended`/`turn_ended` semantics on crash vs clean exit documented in DEVIATIONS if changed.

## Tests
- **Unit**: fold with `compacted` (range replaced, pins verbatim and in order); torn-line handling at
  every byte offset of a sample line; unsettled detection; resume message synthesis; 80 % trigger
  arithmetic; sealing of the summarise request.
- **E2E (mock)**: crash injection: a `KELIR_TEST_CRASH_AT=<n>` test hook (cfg(test)-free but documented as a
  test hook, no-op unless set) that aborts the process at named points (after log write of
  `tool_started`, mid-tool, after `tool_settled`, mid-stream, after `usage`), run the five points,
  resume each, assert: no completed command re-run (use a side-effect file with a counter), the
  unsettled call reported unknown, the session finishes. Compaction: after it, the next request
  contains the task and every human message verbatim and the summary; agent-called, human, and auto
  triggers; a compaction while a tool runs waits for the boundary.
## Live drive (reviewer)
`kill -9`/`taskkill /F` kelir at 5 random points during a real ~10-step task, `resume`, completes
the task; the side-effect counter proves no re-run. Compact a real session with `/compact focus`, ask
a question that needs the pinned task. Check cached tokens after compaction.
