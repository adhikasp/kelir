# M6 — MCP as a CLI

Prereq: M5 green. Read SPEC *MCP as a CLI*, *Event log v0* (`mcp_started`/`mcp_settled`), *Gates*
tool-name `mcp:<server>.<tool>`, *Process model* (session process is the broker).

## Build
1. `config.toml` (config dir, then project `.kelir/config.toml`): `[servers.<name>]` with `command`,
   `args`, `env`, optional `description`, `channel = true|false`. Stdio transport. (HTTP/SSE
   transport is a stretch: only if `rmcp` makes it nearly free.)
2. CLI exactly as the spec: `kelir mcp ls [--json]`, `kelir mcp <server> ls [--detail name|desc|full]`,
   `kelir mcp <server> <tool> [k=v …] [--json '{…}'] [--schema] [--envelope]`. stdout = structuredContent as JSON
   or text blocks joined; images/blobs go to files and their paths are printed. Exit codes 0 ok, 1 tool
   isError, 2 usage, 3 server unavailable, 4 timeout (unknown outcome, never retried). `k=v` values
   parse as JSON when they can, else strings; validate against inputSchema with a clear error.
3. **Broker**: inside a session (`KELIR_SOCK` set), the CLI sends the call over the session socket; the
   session process starts the server lazily, keeps it for the session, and records
   `mcp_started`/`mcp_settled` (with `parent_call_id` = the enclosing bash call). Outside a session the
   CLI spawns the server one-shot. Result > 10 KB spills to the session dir like any output.
   Channel servers are connected at session start (inbound notifications are logged as `source`
   events kind `channel`; handling policy is M10).
4. Use `rmcp` with client features only; justify any other new dependency in docs/DEPS.md. If `rmcp` is
   unavailable or too heavy for the footprint rules, hand-roll the small JSON-RPC subset
   (initialize, tools/list, tools/call, notifications) and record why in DEVIATIONS.md.
5. The hint in M5 (and `observe`) lists configured servers with their descriptions.

## Tests
- **Unit**: arg parsing (`k=v` typing), schema validation errors, exit-code mapping, output
  rendering (structured vs text vs blob), config.toml layering.
- **E2E**: ship a tiny test MCP server (a second binary or a Python script in `tests/support/`,
  stdio JSON-RPC: tools `echo`, `fail` (isError), `slow` (sleeps), `big` (20 KB), `image`) and drive:
  `ls`, tool call through the broker with `parent_call_id`, spill of the big result, timeout → exit 4
  and no retry, server crash → exit 3, one-shot outside a session, call from inside a real bash
  tool call in a mock-driven session (the log shows `tool_started` → `mcp_started` → `mcp_settled` →
  `tool_settled`). Windows and Linux.
