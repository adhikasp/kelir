# M7 — children as CLI, brief, caps

**Design change (maintainer, 2026-11-19): no `spawn` tool.** A child is a kelir process the model starts
from `bash`. Native tools stay `bash`, `edit`, `compact`. Delegation guidance is a builtin skill injected
at M8, not a tool. Nothing of M7 was built before this change.

Prereq: M6 green. Read SPEC *Subagents*, *Process model* (children), *Shell and platforms* (process
tree), event types `child_started`/`child_settled`, `session_started.parent/depth`.

## Build
1. **CLI, not a tool**: `kelir run --child "<task>" [--background] [--model M]` starts a child as a separate
   OS process with its own session dir, `parent` and `depth` in `session_started`. `KELIR_ROOT`,
   `KELIR_PARENT`, `KELIR_DEPTH` are exported to every bash child alongside `KELIR_SOCK`; the CLI registers
   `child_started`/`child_settled` with the **root session's socket** (root stays the only writer of the
   registry and of its own log). Foreground: the bash call's stdout is the child's final result.
   Background: returns a handle at once; completion is a `child_settled` at the next boundary that wakes the
   parent (like `bg`). Outside any session the CLI works standalone (root = itself). The tool list is
   unchanged (`bash`, `edit`, `compact`).
2. Process groups: children live inside the parent's process group (Unix) or Job Object (Windows) so
   killing the parent leaves no orphans — **except** `bg` jobs, which stay detached on purpose.
3. **Caps** in `config.toml`: depth 3 (root 0), 10 children per agent, 16 live descendants per root, **enforced by the
   CLI** against a registry held by the root (atomic, shared across processes; a crashed child must not leak a
   slot: reap by liveness). A start past a cap exits non-zero with a message the model can read and a clear
   count. No spend cap; cost per session and child shown in `kelir ls`.
4. `kelir ls` (sessions tree with state, depth, model, cost, cache hit ratio, task one-liner) and
   `kelir ls --json`; `kelir kill <session|--tree>`; `stop`, `resume`, `observe`, `attach`-style verbs
   work on children unchanged.
5. `brief`: verb + `kelir brief "<question>"`: a child on a by-value snapshot of the parent's
   context (fold at that seq, copied), `edit`/`compact` refused by result (tool list identical
   to the parent so the prefix cache hits; `session_id` reuse for cache stickiness), parent history
   untouched; returns the answer.
6. Only the root session reports the Herdr status; children never write OSC records.

## Tests
- **Unit**: cap arithmetic and registry (concurrent increments), depth propagation, snapshot fold
  by value, refused-tool results for brief, ls tree rendering.
- **E2E (mock)**: child of a child finishes (depth 2); foreground and background spawn; the 11th
  child of one agent refused; the 17th live descendant refused (spawn 16 sleepers); depth 4
  refused; kill parent → no orphan child processes on Windows and Linux (pid checks); background
  child wakes the parent; `brief` request prefix equals the parent's (mock compares) and leaves the
  parent's log untouched except for the `child_*` pair.
