## Introspective pass — what the implementer runs exposed

Only transcript-sourced observations are labelled with seq numbers; the rest cite
diff/notes lines. Ranked by value/effort.

### 1. [HIGH value / LOW effort] A finished gate must leave a machine-readable terminal line — and the loop must not die while waiting on the global lock

**Evidence.** Both implementer transcripts terminate **inside the gate tool call**:
A at seq 191 (`bash scripts/gate.sh --linux=<machine> … | tee …`), B at seq 111 (same).
`m9-gate-console.log` has only three `gate-lock: waiting … held by pid …` lines;
the newest gate dir's `gate.log` ends at `fmt: ok`/`clippy: ok` and `nextest.log`
at case 1040/1334. There is no `gate: PASS`/`gate: FAIL` line, no `turn_ended`,
and no final assistant message in either transcript. The session simply stops.
A main-process `kelir.exe` was also blocked on the same gate lock.
**Change.** In `scripts/gate.sh` emit a terminal `gate: PASS|FAIL` line on *every*
exit path, including the "lock held" path (today it loops in `scripts/gate-lock.sh:325`
printing `waiting` forever with no timeout). Add a `--lock-timeout SECS` (default,
say, 600) so a blocked gate fails with `gate: FAIL (lock timeout)` instead of
starving the session. In `src/prompt.md`, add one line under the verify bullet:
`- A gate that blocks on the global lock is not progress: if it waits more than a\n  few minutes, report the block and stop; never leave a turn open on a lock wait.`

### 2. [HIGH value / LOW effort] Discourage full-file `cat` of big docs in the prompt (already a FINDINGS item, still bleeding)

**Evidence.** `docs/retros/FINDINGS.md` (2026-11-19 concurrency item c) says workers
re-read DEVIATIONS.md/SPEC.md in full and `cat` of big files should be discouraged.
The implementer did exactly that: seq 21 `cat docs/tasks/M9.md && … cat
docs/PROGRESS.md … cat docs/retros/m9-impl-notes.md`, seq 26 `cat docs/tasks/M9.md`
**again** (after a 63,390-byte result at seq 22), seq 51 `cat
docs/retros/m9-impl-notes.md`, session B seq 21 `cat docs/PROGRESS.md`. The prompt's
read rule (`src/prompt.md:13-16`) says "no big `cat`" but only in the context of
"one bash call per read round"; it is easy to read as a batching hint, not a ban.
**Change.** Strengthen `src/prompt.md:13-16` to an explicit rule:
`- Never \`cat\` a whole file you have not sized: \`wc -l\` first, then \`sed -n\n  a,bp\` or \`rg -n\` the section you need. Re-read a file only when it changed; do\n  not \`cat\` the same doc twice in one turn.`
Cheap, no code, closes a known token sink (sum prompt tokens 1.4M across the two runs).

### 3. [HIGH value / MEDIUM effort] Turn-completion events on tool failure/abrupt end; a session must not vanish silently

**Evidence.** Both sessions end on a `tool_started` with no matching
`tool_settled` (A: 38 started / 37 settled; B: 22 / 21) and no `turn_ended`.
Whatever killed them left no recorded reason. The brief's own `FINDINGS.md` has a
same-class item ("who killed me" hunt, 0xC000013A).
**Change.** In `src/session.rs` (the drive/turn-end path, near `TurnEnd` at
`:579-614`) ensure an abrupt parent/tool-loop exit emits a `turn_ended` with
`outcome: error` and a reason field before the process goes away where possible;
add a `bash` tool timeout/heartbeat in `src/tools/bash.rs` so a gate command that
hangs on a lock is settled instead of left open. Document the new terminal field
in `src/docs/tables.rs` + `docs/reference/events.md` and run `kelir docs --generate`.

### 4. [HIGH value / LOW effort] Tell the job model the *budget* in the one source line, not just the paths

**Evidence.** The single job source line (`src/jobrun.rs:277-283`) lists STATUS,
history, notes — but not the job's `max_steps`, `timeout`, or the deadline.
`FINDINGS.md` M5-A records a step-cap failure that "read as a failure" and the
follow-up decision that a cap should say "turn paused, say continue". A scheduler
job under a cap/timeout is exactly where the model needs to know its budget.
**Change.** Extend the `format!` at `src/jobrun.rs:277-283` with one clause:
`" This run allows at most {max_steps} steps and {timeout} wall clock."` (omit
each when unset), sourced from the validated `def.max_steps`/`def.timeout` already
in scope. No prompt growth; stays one tail source. Add an assertion in
`tests/e2e_m9.rs:337-344`.

### 5. [MEDIUM value / LOW effort] Name the cache-break in the job source line so the model does not re-derive the date

**Evidence.** `clock_source` appends "it is now <date>" (`src/jobs.rs:446-454`),

looks old, so a diligent agent may "fix" it. Documented deviations already note

**Change.** In `src/session/jobhooks.rs:14-21`, when pushing the clock source,

### 6. [MEDIUM value / LOW effort] `--wait` needs a visible "queued" STATUS and a jitter hint in the CLI help

**Change.** Add `KELIR_JOB_WAITING=<secs>` to the `--wait` process env (in

### 7. [MEDIUM value / LOW effort] Per-run cost is structurally unknown on free models — say so in STATUS.md

### 8. [MEDIUM value / MEDIUM effort] Reuse the gate's `/proc` token sweep for Unix notify hooks
